# OpenCode Telegram Bot — Railway Edition

A Telegram client for OpenCode designed to run continuously on Railway. Control OpenCode, run coding tasks, manage sessions, switch models, browse files, answer agent questions, schedule tasks, and configure custom AI providers directly from Telegram.

This fork adds a Railway-oriented container setup: OpenCode runs inside the same container, runtime data is stored under `/data`, and normal Telegram polling does **not** require a public Railway domain or exposed OpenCode port.

## Architecture

```text
Telegram
   │
   ▼
Telegram Bot
   │
   ├── OpenCode API → 127.0.0.1:4096
   ├── Custom providers → /data/providers + generated OpenCode config
   └── runtime data → /data

Railway Volume
   └── /data
```

## Railway deployment

### 1. Deploy the repository

Deploy the `main` branch of:

`aminsh35322088-ctrl/opencode-telegram-bot`

The repository contains the Railway Dockerfile and entrypoint.

### 2. Attach a persistent Volume

Create a Railway Volume and mount it at exactly:

```text
/data
```

This keeps bot/OpenCode runtime data and custom provider credentials across redeployments and restarts.

### 3. Required environment variables

| Variable | Required | What to enter |
|---|:---:|---|
| `TELEGRAM_BOT_TOKEN` | ✅ | Token generated by @BotFather |
| `TELEGRAM_ALLOWED_USER_ID` | ✅ | Your numeric Telegram user ID |
| `OPENCODE_MODEL_PROVIDER` | ✅ | Default provider, e.g. `opencode` |
| `OPENCODE_MODEL_ID` | ✅ | Default model ID, e.g. `big-pickle` |

Keep secrets in Railway and never commit their values to GitHub.

### 4. Recommended Railway variables

| Variable | Recommended value | Purpose |
|---|---|---|
| `OPENCODE_API_URL` | `http://127.0.0.1:4096` | Local OpenCode API |
| `OPENCODE_AUTO_START_IN_CONTAINER` | `true` | Start OpenCode inside the container |
| `OPENCODE_AUTO_RESTART_ENABLED` | `true` | Restart OpenCode after failed health checks |
| `OPENCODE_MONITOR_INTERVAL_SEC` | `60` | Health-check interval |
| `OPEN_BROWSER_ROOTS` | `/app/workspace` | Directory available to `/open` |
| `BOT_LOCALE` | `en` | Bot language |
| `LOG_LEVEL` | `info` | Runtime logging level |

### 5. Telegram User ID

Send any message to [@userinfobot](https://t.me/userinfobot) and use the numeric ID it returns for `TELEGRAM_ALLOWED_USER_ID`.

### 6. Public domain and ports

For normal Telegram polling:

- **No Railway public domain is required.**
- **Do not expose port 4096 publicly.**
- OpenCode uses `127.0.0.1:4096` inside the container.
- Telegram communicates with the bot through outbound Telegram Bot API requests.

## Custom AI providers

You do **not** need a new Railway environment variable for every API.

Open **Settings → API Providers** or use `/providers` in Telegram. The wizard asks for:

1. Provider name
2. Base URL, e.g. `https://tabitoken.com/v1`
3. API key

The bot validates the provider by calling its OpenAI-compatible `/models` endpoint, discovers available models, stores the API key in a private file under `/data`, generates an OpenCode custom-provider config, and restarts the local OpenCode server so the provider becomes available immediately.

API keys are never displayed back by the bot, and the Telegram message containing the key is deleted when Telegram permits it.

This supports OpenAI-compatible APIs using `/v1/chat/completions` and OpenCode's `@ai-sdk/openai-compatible` provider adapter.

See `docs/CUSTOM_PROVIDERS.md` for details.

## Telegram commands

| Command | Description |
|---|---|
| `/status` | Server health, project, session, and model |
| `/new` | Create a new session |
| `/abort` | Abort the current task |
| `/detach` | Detach without stopping the session |
| `/sessions` | Browse and switch sessions |
| `/messages` | Browse messages, revert, or fork |
| `/projects` | Switch OpenCode projects |
| `/worktree` | Switch Git worktrees |
| `/open` | Browse and add a project directory |
| `/ls` | Browse, open, and download files |
| `/settings` | Change bot runtime settings |
| `/providers` | Manage custom OpenAI-compatible providers |
| `/rename` | Rename the current session |
| `/commands` | Browse and run custom commands |
| `/skills` | Browse and run OpenCode skills |
| `/mcps` | Browse and toggle MCP servers |

Regular text messages are sent to the current OpenCode session. Voice/audio messages are supported when STT is configured.

## Models

Set a valid default provider and model ID before starting the bot:

```text
OPENCODE_MODEL_PROVIDER=opencode
OPENCODE_MODEL_ID=big-pickle
```

After startup, models can be switched from Telegram using the model picker.

## Persistence and workspace

The Railway Volume should be mounted at `/data`. The container uses `/data` as its runtime home and XDG data/cache/config location.

The default Railway project workspace is `/app/workspace`. If project files must survive redeployments, store them under the persistent volume or configure `OPEN_BROWSER_ROOTS` to a persistent location.

## Updates

The container installs the OpenCode version recorded in `.opencode-version`. The repository's update workflow can change that file and commit the new version; Railway's GitHub integration can then automatically rebuild and deploy it.

## Security

- Keep `TELEGRAM_BOT_TOKEN` secret.
- Set `TELEGRAM_ALLOWED_USER_ID` to your own numeric Telegram ID.
- Users outside the allow-list are rejected.
- Custom provider API keys are stored under `/data` with restricted file permissions and are not committed to Git.
- OpenCode is local to the container and does not need to be exposed publicly.
- Do not expose the OpenCode API publicly unless you intentionally configure authentication and networking.

## Local development

Requirements: Node.js 22.14+, OpenCode, a Telegram bot token, and your Telegram user ID.

```bash
npm ci
npm run build
npm start
```

For local usage, OpenCode normally listens at `http://127.0.0.1:4096`.

## Troubleshooting

### Bot does not start

Verify these four variables are non-empty:

```text
TELEGRAM_BOT_TOKEN
TELEGRAM_ALLOWED_USER_ID
OPENCODE_MODEL_PROVIDER
OPENCODE_MODEL_ID
```

### Custom provider is not visible

Open `/providers` and confirm that the provider was saved and models were discovered. Then use `/models`. The bot restarts the local OpenCode server after saving a provider.

### OpenCode is unreachable

Verify:

```text
OPENCODE_API_URL=http://127.0.0.1:4096
OPENCODE_AUTO_START_IN_CONTAINER=true
```

Then inspect Railway runtime logs for the OpenCode startup line.

### Data disappears after redeploy

Verify the Railway Volume is mounted at exactly `/data`.

### Telegram connectivity problems

Configure `TELEGRAM_PROXY_URL` or a custom `TELEGRAM_API_ROOT` if direct Telegram API access is unavailable. Do not configure both.
